# Story revision：让已有研究形成可跟随的论证

仅在用户明确要求故事、逻辑或结构修订时使用。改写叙事不等于重新设计研究；先尊重已经确定的研究目标与判断标准。

## 选择中心，而不是统一套模板

用一句话回答：“这项研究希望读者重新判断什么，已有证据支持到哪里？”若尚无结果，写研究问题与计划，不能提前写结论。

公开语料展示多种可行路径：

- **概念推导**：定义对象 → 推出关系 → 得到可训练方法 → 验证用途。适合概念确实承担方法的研究，见 H02、H10。
- **合理默认遇到新条件**：旧选择为何合理 → 条件改变 → 直接迁移的困难 → 有针对性的设计。见 X02、X06。
- **区分竞争解释**：现象 → 可区分的解释 → 已有干预/对照 → 有范围的结论。见 X07。
- **经验设计研究**：固定关键条件 → 比较选择 → 发现 → 更细的问题。见 H03、X04、X09。
- **实践改进**：具体使用摩擦 → 选择与代价 → 对实际目标的意义。见 H06、X01。
- **诊断成功的含义**：总分/样例看似成功 → 拆开能力或误差 → 显露剩余问题。见 X05、X08、X10。

不用把局部工程改进写成新范式，也不用为简单而有价值的经验发现增加模块。上述路径可以混用，但每次转换要由材料支持。

## 最小工作材料

从用户给出的材料提取，缺少时注明，不虚构：

1. 研究问题与适用对象。
2. 已确认的设计、数据和协议。
3. 每项贡献对应的现有证据与边界。
4. 待完成结果与尚未核实的文献事实。

把“主张 → 现有证据 → 适用条件”配在一起。没有证据不是自动开新实验的命令：在本次写作内可以改成目标/假设、收窄、合并或标为缺口。若需要作者作研究决策，再提出具体问题。

## 重排的判断标准

- 新术语出现前，读者是否已理解要解决的具体困难？
- 每段是否完成一个主要论证动作，并为后文留下对象、问题或结论？
- 方法顺序是否跟随概念依赖，而非文件/代码模块顺序？
- 实验顺序是否让读者逐步回答主张，而不是逐张报表？
- 最近邻方法是否在相关技术决定处获得准确归属？专门Related Work可前可后。
- 主文是否保留会改变公平性、可行性和贡献含义的条件？长配置和推导才适合后移。

章节顺序、贡献条数、是否有独立Analysis/Conclusion都不是统一规定。

## 原创重组示例

以下设定是虚构教学输入，且作者明确允许重组：一个压缩模型比较两种位深，目标是检验更小表示能否保持重建质量；只完成一个数据集的结果，较低位深与较高位深误差相同、内存更低；延迟尚待测量。

Before: “We introduce a new compression framework with two settings. We conduct experiments on a dataset. Memory is important for deployment. The results show equal reconstruction error and lower memory use. Runtime evaluation is planned.”

After: “Memory matters for deployment. We compare two bit-depth settings to test whether a smaller representation can retain reconstruction quality. On the evaluated dataset, the lower-bit setting matches the reconstruction error of the higher-bit setting while using less memory. Runtime evaluation remains pending.”

收益：问题 → 比较问题 → 有范围的已测结果 → 未测状态；不是新增理论或实验。没有把更低内存推成更快、没有扩大到多数据集。“deployment”动机来自输入，不能套到未提供这一动机的其他论文。

## 不应越过的边界

- 作者关注固定预算的平均效果，不改成等性能节省或每任务必胜。
- 结果显示一个权衡，不自动改成功能全胜；重要性可以来自新的能力或实际代价。
- 收紧主张必须有理由；不能习惯性堆免责声明，把贡献写没。
- 增加解释、删掉条件、移动事实到摘要，都应说明它来自哪里及为何合理。

交付时分清：论证次序变化、贡献表述变化、纯语言变化、仍需作者决策。故事更易跟随可以成立，但若问题、方法与证据未变，不能因此声称研究贡献变强。
